# 客户线索 AI 评分

**什么时候用**：用户要对 CRM 里的客户线索做「评分 / 打分 / 质量评估」，或说「把高分线索挑出来」「评估线索成单概率」「给线索排名」。
**什么时候别用**：只是想查某条线索的原始字段（岗位、预算、电话……）直接 `crm_query`，不要跑本技能。

## 评分规则（满分 100，脚本已精确实现）

| 维度 | 分值 | 规则 |
|---|---|---|
| 岗位 | 20 | 产品类（产品经理/技术/工程师/数据/设计/研发/开发/创业）20；学生 0；其余 10 |
| 预算 | 20 | 预算区间中位数 2000~5000 元 → 20；>5000 → 10；<2000 → 0 |
| 行为 | 30 | 试听 >60 分钟 → 30；10~60 分钟 → 15；<10 分钟 → 0 |
| 互动 | 10 | 沟通 ≥3 次 → 10；2 次 → 5；≤1 次 → 0 |
| 渠道 | 20 | 朋友圈 → 20；抖音 / 搜索引擎 → 10；线下海报 / 其他 → 0 |

评分必须由脚本计算，**不要自己心算**——预算区间解析、边界判断（>60 分钟、≥3 次）都要精确。

## 步骤（必做，一步一步来）

1. 用 `write_todos` 建过程清单，至少含：读取脚本 / 执行评分 / 汇总输出 /（如需）发送飞书。每完成一步立刻标 completed。
2. **执行评分脚本**（命令照抄，用 venv 相对路径，别用裸 `python`）：

   ```
   libs\deepagents\.venv\Scripts\python.exe chat-ui\skills\lead-scoring\scripts\score_leads.py --unconverted --limit 20 --out chat-ui\static\reports\lead_scores.json
   ```

   参数说明：
   - `--unconverted` 只评**未成单**（status ≠ 成交）线索；`--all` 评全部；`--ids LD-xxx,LD-yyy` 评指定。
   - `--limit N` 取最新 N 条（按创建时间倒序），用户说「最后 N 条」就带它。
   - `--min-total 80` 只保留总分 ≥ 80 的线索。
   - `--out <路径>` 把结果写成 JSON 文件，stdout 会回 `RESULT_FILE=...` 与 `TOTAL=...`。
3. `read_file` 读 `RESULT_FILE` 指向的 JSON，拿到每条线索的 5 项得分、依据和总分。
4. 按下面的「输出格式」整理成 Markdown 文字回复。

## 输出格式（只给 Markdown 文字，不要卡片）

**单条线索**：列出 5 个维度的得分和依据，再给总分。例如：

```
线索「王小明」（LD-2026-0001）评分：总分 85
- 岗位 20/20：产品经理（高相关）
- 预算 20/20：3000-5000 元，命中 2000~5000 区间
- 行为 30/30：试听 180 分钟（>60 分钟）
- 互动 10/10：沟通 5 次（≥3 次）
- 渠道 5/20：抖音
```

**多条线索**：用 Markdown 表格，按总分从高到低排，列：排名、线索名、手机号、岗位、预算、试听、沟通、渠道、总分。表格后单独列出「总分 ≥ 80 的高分线索」名单。

## 如需发飞书（用户说「发给 XX」时）

1. `feishu_search_contacts("<人名>")` 找到对方的 open_id；
2. `feishu_send_message(receive_id=open_id, text=<评分结果文字>, receive_id_type="open_id")` 发私聊。
   文本 = 高分线索的 Markdown 表格/清单（姓名、手机号、总分、关键依据）。

⚠️ 如果 `feishu_search_contacts` 返回「尚未授权」或找不到对方，**绝不要假装发送成功**——如实说明「搜通讯录未授权 / 未找到对方，无法发送飞书」，并把评分结果照常在正文里展示，同时提示用户先完成飞书授权。

## 硬性要求

- 只输出评分结果和依据，**不要**写「我先读取技能说明 / 我正在执行脚本」这类过程性文字，也不要粘贴脚本原始 JSON。
- 依据要和脚本 `reason` 字段一致，不要自己编。
- 评分结果里**必须给手机号**（发飞书、联系客户都要用）。
