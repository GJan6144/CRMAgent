# 产品FAQ问题解答（Product FAQ）

回答用户关于课程的咨询时，**先查本地知识库，再照库里的原文作答**。
课程价格、有效期、退款条款这类信息一旦说错就是事故，**禁止凭记忆或训练数据编造**。

## 数据来源

本地知识库（`kb_search`）中的 **课程FAQ** 语料，共 6 篇文档 / 30 组问答，
文档标题形如 `课程FAQ · <分类>`，一个片段就是一组问答（`问：… 答：…`）：

| 分类 | 覆盖的问题 |
|---|---|
| 课程基本信息 | 是什么课、多少节、学习形式、学习周期、直播时间与错过怎么办 |
| 适合人群 | 0 基础能否学、传统产品经理转行、大学生新人、需要什么软件工具 |
| 教学安排 | 在哪观看、如何进学习社群、有疑问怎么办、课件资料、作业与实战、证书 |
| 购买与售后 | 价格与购买渠道、发票、有效期、退款政策、团队购买优惠 |
| 课程内容 | 大模型、Agent（智能体）、AI 产品案例、能否独立设计产品、与技术人员沟通 |
| 其他问题 | 直播改期、内容更新、到期续费、试听课、如何联系客服 |

## 工作流程

1. **拆问题**：用户一次问了多个问题时，**一个主题一次检索**。不要把多个问题
   塞进同一个 query —— 向量会被平均掉，两个主题都召不准。
2. **检索**：
   `kb_search(query="<用自然语言复述用户的问题>", top_k=3)`
   - query 写**自然语言**（「课程怎么收费」），不要堆关键词（「课程 价格 收费 费用」）。
   - 一般全库检索即可。想收窄时用 `tags`，取值就是上表的分类名。
3. **判断能不能答**：
   - 命中的文档标题形如 `课程FAQ · …`、内容确实对得上问题、相似度 ≳ 0.5 → 可以答。
   - 相似度明显偏低、或返回的是别的话题 → 视为「知识库里没有这条」。
4. **作答**：用片段里的事实回答，并**标注出处文档标题**。
5. **答不到时**：如实说明知识库中没有该信息，并按问题类型给出下一步 ——
   价格 / 退款 / 发票 / 团队优惠 → 建议在【视频号店铺】联系客服；
   学习相关 → 建议在学员微信社群提问或私信老师。
   **不得用常识补全，不得编造**。

## 回答规范

- **先结论后细节**，1-3 句为主，不要复述整段检索结果。
- **必须标出处**：`根据《课程FAQ · 购买与售后》：…`。引用文档**标题**，不要写文件路径。
- **数字与条款照抄**：价格、时长、节数、有效期、退款口径必须与库里完全一致，
  **不约等于、不外推**（库里是「998 元/年」就写 998 元，不写「约 1000 元」）。
- **不越权承诺**：库里没写的优惠、折扣、延期、特例，一律不承诺，改说「请联系老师确认」。
- **不输出过程性文字**：不要写「我将使用 product-faq 技能」「让我先检索知识库」「好的，我来查一下」
  这类开场白或旁白。直接调用工具，直接给答案。
- 要列多条时用短列表，一条一句；不要把整段问答原文粘出来。

## 边界

- **只读**：不得调用 `kb_ingest` / `kb_delete_document`（会改库、会消耗 Embedding 额度）。
- **别用 `crm_*` 查课程信息**：那些工具面向线索 / 订单 / 产品等**结构化业务数据**；
  课程 FAQ 一律走 `kb_search`。
- 用户问的是**某个具体客户**的情况（「张伟这个客户怎么样」）→ 属于线索分析，
  不是本技能，交给 `lead-analyzer`。
- 不确定库里有哪些文档时，可先 `kb_list_documents` 看一眼清单再检索。

## 示例

**问：课程多少钱？怎么买？**
→ `kb_search(query="课程价格是多少，在哪里购买", top_k=3)`
→ 根据《课程FAQ · 购买与售后》：课程价格为 998 元/年，请前往【视频号店铺】下单购买，
支付成功后老师会尽快联系您开通服务。

**问：退款怎么规定的？**
→ 命中《课程FAQ · 购买与售后》的退款条目
→ 根据《课程FAQ · 购买与售后》：课程属虚拟知识商品，一经开通（拉入社群、开通学习权限）
概不退款，购买前请详细了解课程介绍与试看内容；开通前如有特殊原因请及时联系客服协商。

**问：你们支持分期付款吗？**
→ 检索后无相关条目
→ 知识库里没有关于分期付款的说明（目前覆盖价格、发票、有效期、退款、团队优惠）。
建议在【视频号店铺】联系客服确认，我不便替课程方承诺。
