# 客户线索分析（Lead Analyzer）

对单个客户线索做全方位分析，辅助销售制定跟进策略。**只读**：全程不得调用写入类工具
（`crm_create` / `crm_update` / `crm_delete`），分析结论不得写回 CRM。

**结论以数据卡片呈现**：分析完成后调用 `render_card`，把结论放进卡片，而不是写一大段 Markdown。

## 使用场景

- 用户给出客户姓名、手机号、线索编号（如 `LD-2026-0011`），要求评估这个客户
- 用户问「这个客户购买意向如何 / 为什么没成交 / 提到了哪些竞品 / 该怎么跟进」
- 销售希望在跟进前快速了解某客户的情况

## 数据来源

CRM 中与本技能相关的实体（先调用 `crm_list_entities` 确认字段，若已了解可直接用）：

| 实体 | 说明 | 关键字段 |
|---|---|---|
| `leads` | 销售线索（客户主档） | `id`、`name`、`phone`、`priority`（high/medium/low）、`source`、`assignee`、`status`、`intentProduct`、`budgetRange`、`customerPosition`、`trialDuration`、`communicationCount`、`remark`、`lastFollowUpAt`、`createdAt` |
| `communications` | 沟通记录 | `id`、`leadId`、`sentAt`、`sender`、`senderRole`（销售/客户）、`content`、`type`、`channel` |
| `orders` | 订单（用于判断是否已成交） | `orderNo`、`customerName`、`customerPhone`、`productName`、`amount` |

`leads.status` 常见取值：`成交`、`客户流失`、`未接触`、`价格异议`、`推荐产品`、`长期未跟进`。

## 工作流程

严格按以下顺序执行，**不要跳步**：

### 第 1 步 · 定位线索

用户可能只给姓名、手机号或编号，需先解析出唯一的 `lead_id`：

- 给了线索编号 → 直接进入第 2 步。
- 给了姓名 / 手机号 / 关键词 →
  `crm_query(entity="leads", keyword="<姓名或手机号>", limit=20)`
  - 命中 **1 条** → 取其 `id`。
  - 命中 **多条** → 列出候选（编号 / 姓名 / 来源 / 状态 / 跟进人），请用户确认是哪一个，**不要凭猜测选一个**。
  - 命中 **0 条** → 告知未找到，并建议用户核对姓名或手机号。

### 第 2 步 · 读取线索详情

`crm_get(entity="leads", record_id="<lead_id>")`

拿到客户主档：优先级、来源、状态、意向产品、预算区间、职位、试用时长、备注、沟通次数等。

### 第 3 步 · 读取沟通记录（分析的核心依据）

`crm_query(entity="communications", filters='{"leadId":"<lead_id>"}', sort_by="sentAt", order="asc", limit=200)`

- **务必按 `sentAt` 升序**读取，才能还原对话脉络（谁先开口、诉求如何变化、在哪一步卡住）。
- 若记录为空，说明该线索尚无沟通，须在卡片中如实说明「暂无沟通记录」，并据线索自身字段给出保守判断，**不得编造对话内容**。

### 第 4 步 · （条件执行）核对订单

若 `status` 为 `成交`，或沟通中提到已付款 / 已报名，可用客户手机号或姓名核验是否有订单：
`crm_query(entity="orders", keyword="<phone 或 name>", limit=20)`

### 第 5 步 · 输出数据卡片

完成分析后**调用 `render_card`**（见下方「卡片输出规范」）。每一条结论都必须能追溯
到具体字段或沟通原话，避免空泛套话。

## 分析要点（五问的判定方法）

### 1. 购买意向：高 / 中 / 低

综合以下信号判断，并在结论后附**判断依据**：

- **偏高的信号**：主动询问价格 / 开课时间 / 报名方式、明确说出自己的目标（如转行、升职）、关心课程细节、承诺「考虑一下」以外的具体行动、状态为 `成交`。
- **中等的信号**：表达兴趣但态度观望、只做泛泛咨询、反复比较但未拒绝、长时间未再联系、状态为 `推荐产品`。
- **偏低的信号**：只回一句就消失、明确说预算不足或暂不需要、选择竞品、状态为 `客户流失` 或 `长期未跟进` 且无正向互动。

同时参考线索字段：`priority`、`trialDuration`（试用时长越长通常意向越强）、`communicationCount`、`status`。
`未接触` 类线索通常只能给「待定」，应说明依据不足及所需补充的信息。

### 2. 感兴趣的产品

- 优先取 `leads.intentProduct`；
- 再结合对话中客户自述的需求（例如「想转行做 AI 产品经理」→ 对应 AI 产品经理相关课程）交叉验证，若二者不一致要指出差异；
- 若客户询价对应了具体课程 / 报价，注明沟通中出现的产品名与价格。

### 3. 交易未达成的原因

若已成交，则说明成交的关键推动因素，并明确「本单已达成」。
未成交时，从对话里定位**卡点**，常见类型与线索：

- **价格异议**：客户说「太贵」「能不能再优惠」，销售未让步 → 价格敏感。
- **信任顾虑**：追问师资、口碑、退款政策等。
- **时间顾虑**：担心没时间学习、排期不合适。
- **决策延迟**：说「再考虑一下」「和家人商量」后失联。
- **竞品分流**：客户选择了或倾向了其他机构。
- **无明确拒绝但无后续**：销售未推进或客户沉默 → 跟进不足。

给出**具体原因 + 对话证据**，不要只写「价格原因」四个字。

### 4. 是否提及竞品

- 检索沟通内容中的机构 / 产品名（如「知乎课堂」「起点学院」等）与对比性表述（「你们和它们比优势在哪」「别家更便宜」）。
- 有 → 逐个列出：**竞品名称 + 客户提及的语境 + 客户看重的点**。
- 无 → 明确写「沟通中未提及竞品」，不要留空或臆测。

### 5. 后续跟进建议

给出**可立即执行**的建议，而非泛泛而谈。至少覆盖：

- **跟进时机**：多久联系一次、下次触达的合适时间点（可结合 `lastFollowUpAt` 与客户的顾虑类型）。
- **跟进渠道**：微信 / 电话 / 邮件（参考既有沟通 `channel`）。
- **沟通切入话术 / 素材**：针对第 3 条的原因准备对应素材（如价格敏感 → 优惠 / 分期 / 附加价值；信任顾虑 → 学员案例、师资介绍）。
- **成交推进动作**：约试听、发课程大纲、限时优惠、约线上答疑等具体下一步。
- **风险提示**：该客户流失的风险点及需避免的失误。

## 卡片输出规范

分析完成后**必须调用 `render_card`**，用它承载全部结论：

```
render_card(
  card_type = "lead_analysis",
  title     = "客户线索分析报告：<客户姓名>（<线索编号>）",
  data      = "<一个 JSON 对象的字符串>"
)
```

### data 的结构

```json
{
  "meta": [
    {"label": "线索编号", "value": "LD-2026-0002"},
    {"label": "来源", "value": "官网表单"},
    {"label": "当前状态", "value": "客户流失"},
    {"label": "优先级", "value": "high"},
    {"label": "跟进销售", "value": "王芳"},
    {"label": "沟通次数", "value": "6 次"}
  ],
  "sections": [
    {"label": "购买意向", "value": "高 · 曾两次主动询价并问到开课时间", "tone": "high"},
    {"label": "感兴趣产品", "value": "AI 产品经理实战班（客户自述想转行 AI 方向）", "tone": "info"},
    {"label": "未成交原因", "value": "价格异议：客户提出「能否减免一部分」，销售未让步，之后失联", "tone": "warn"},
    {"label": "提及竞品", "value": "知乎课堂 · 客户称对方便宜约 2000 元，但更认可我们的师资", "tone": "warn"},
    {"label": "跟进建议", "value": "3 天内微信回访；带上学费分期方案与 2 个转行学员案例；目标是约一次线上试听", "tone": "info"},
    {"label": "沟通摘要", "value": "03-02 客户：咨询课程价格\n03-05 销售：发送课程大纲\n03-09 客户：表示别家更便宜\n03-15 销售：未再跟进", "tone": "neutral"}
  ]
}
```

### 填写要求

- `meta`（可选）：线索概览，**最多 6 项**，用短标签 + 短值，不要塞长句。
- `sections`（必填，**不能为空**）：按顺序写
  **购买意向 → 感兴趣产品 → 未成交原因 → 提及竞品 → 跟进建议**，
  最后可加一条「沟通摘要」。**最多 8 项**。
- `tone`（可选）：给该条上状态色，取值仅限
  `high`（正向 / 意向强）、`mid`（中性）、`low`（弱 / 负向）、`warn`（需注意 / 风险）、
  `info`（提示 / 建议）、`neutral`（无倾向，缺省）。
  - 购买意向按判断结果取 `high` / `mid` / `low`；
  - 未成交原因、提及竞品通常取 `warn`；跟进建议取 `info`。
- 值里若有多行，用 `\n` 换行，**不要在 JSON 字符串里直接敲回车**。
- 字段值保持精炼：单项 1-3 句，宁可短也别堆砌原文。

### 调用之后

- 卡片已经承载全部结论，**不要再把同样的内容重复写成一大段 Markdown**。
- 可以在卡片之后补 1-2 句话点出**最需要关注的那一点**（例如最大的流失风险、最该做的下一步），也可以什么都不写。不要复述卡片条目。
- 卡片会在对话流中即时展示，并随消息保存（刷新后仍在），无需再做别的操作。

### 兜底

若 `render_card` 调用失败或该工具已被关闭，改用一个 `lead-card` 围栏代码块输出**同样的 JSON**：

````
```lead-card
{"title": "客户线索分析报告：李小红（LD-2026-0002）", "meta": [...], "sections": [...]}
```
````

## 注意事项

- **只读**：不得调用任何写入类 CRM 工具。
- **有据可依**：每条结论都要基于线索字段或沟通原文；找不到依据就写「信息不足」，不得编造。
- **不臆测客户**：姓名 / 手机号命中多条时先向用户确认，不要擅自选一条分析。
- **脱敏**：不要在卡片中输出客户的完整身份证号、密码等敏感字段。
- **精炼**：结论优先、要点清晰，避免堆砌原文；卡片不承载大段引述。
- **不输出过程性文字**：不要写「我将使用 lead-analyzer 技能」「让我先读取…」「好的，我来分析…」之类的开场白或旁白。分析过程中如需调用工具，直接调用，不要先宣告。
